## Release approval

PR CI produces an **unsigned, non-installable update candidate** and metadata using `scripts/android_release.py` gates. It does not access signing secrets, create a release or publish an APK.

After the final immutable source SHA passes CI and owner acceptance, use the existing **Android release (manual approval)** workflow with:

- source_sha: the final reviewed 40-character #112 source commit
- release_tag: `android-v0.6.0-beta.2`
- channel: `experimental`
- publish: `false` for a further unsigned validation; `true` only after explicit release approval

Signing/publication remains behind the `android-release` environment. The workflow verifies the established certificate SHA-256 `c3e4f56d7ebc66329585197c492635ffb457e7c0d0d273e16f16a43e72ccf578`, package/version, non-debuggable APK and packaged notices, and publishes one APK plus its checksum as a prerelease with latest=false. Obtainium keeps the same repository/tag channel and package. Update the existing installation; do not uninstall or clear app data. Never distribute the debug or unsigned candidate as an update to the signed beta.
