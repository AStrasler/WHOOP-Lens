## Automated and manual security checks

- **Semgrep** (OSS `semgrep-rules`: javascript, kotlin and generic secrets) over `cloudflare/src`, `cloudflare/oauth`, `android/app/src/main` and the browser modules: 61 findings, **0 in files changed by the five PRs**. The rest are pre-existing style or regex notices (for example `replaceAll`, ReDoS heuristics in `ai-summary.mjs`, HTML template strings that use `escape()`). They were triaged; none is actionable for this release.
- `npm audit --omit=dev` (cloudflare): 0 vulnerabilities.
- Android lint (CI) passed. The release script still rejects unexpected Bluetooth or location permissions and packaged private material.
- No keystores, secrets or credentials are tracked.
- Manual inspection:
  - BLE service: not exported, starts only on user tap, `START_NOT_STICKY`, immutable explicit PendingIntents, no readings in the notification, private lock-screen visibility, stops when the notification is hidden or blocked, account and permission re-check on every callback, one standard CCCD write, no network.
  - MCP tools: verified identity only, exact arguments, confirmation constants, flag gating, membership and schema fences, safe errors.
  - Cloud sync client: path allowlist, no redirects, bounded responses, account and permission fencing.
  - Widget size readout: launcher dp bounds only.

## Residual risks

- No Codex Security Review result (see above).
- Background BLE timers use uptime; a retry or timeout can run late while the CPU sleeps (no `WAKE_LOCK` by decision).
- The 4×2 widget maximum is launcher-dependent and unverified on One UI (#130).
- None of this release has been tested on hardware yet (#129, #130, `0.7.0-beta.1-acceptance.md`).
