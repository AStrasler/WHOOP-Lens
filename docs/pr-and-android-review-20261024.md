## Android review and implemented fixes

The complete companion source, manifest, build/signing configuration, rationale screen, Keystore adapter, credential cipher, manual sync controls, resources and tests were inspected. The existing scroll layout and visual design were preserved.

1. **Refresh/status interference:** the 30-second polling thread overwrote preview and sign-out messages and ran even while signed out. Refresh is now scheduled at the saved token's refresh deadline, with the existing bounded network-failure backoff. Signed-out and pending-browser sessions do not poll. Account status and preview results have separate views, so normal refresh does not erase the result being read.
2. **Short token lifetime:** a focused regression test reproduced immediate staleness for a valid 60-second token. The refresh margin is now 10% of lifetime, capped at 60 seconds: 60-second tokens refresh after 54 seconds; one-hour tokens after 59 minutes. The new encrypted `refreshAt` field is backward compatible with existing saved sessions, and an upgrade test verifies this.
3. **Restored permissions/reconnection:** after restart, a valid saved session did not re-enable previews unless the chooser was opened again. Resume now checks currently granted Health Connect permissions off the UI thread and restores only permitted controls. Revoked steps permission disables an existing review; unrelated permitted previews remain available. A transiently expired offline session offers **Retry saved connection** without clearing encrypted credentials or starting a new login.
4. **Callback/lifecycle race:** sign-out or a new sign-in while a browser callback was in flight could leave its busy flag set. A small callback ticket guard rejects duplicate/stale completions and releases cancellation correctly. OAuth PKCE, encrypted one-time state, replay checks, atomic refresh rotation and exact callback validation remain in place.
5. **Preview/account isolation:** reconnect, sign-out and a detected shared-session account-generation change clear prepared and visible previews. Account-generation changes invalidate stale UI callbacks; token refresh itself does not count as an account change. Secure-storage failures are caught in sign-in/sign-out UI and fail closed with a generic message rather than an uncaught crash.
6. **System bars and accessibility:** both scroll screens now apply status/navigation/caption-bar and display-cutout insets, use light system-bar icons against the existing dark palette, and expose headings to accessibility services. Account/preview status uses polite announcements only when changed. Disabled buttons use a distinct readable text state; existing 48dp minimum action height, scrolling and scalable text are retained. Insets are required for target SDK 35 on Android 15; implementation follows [Android's Views guidance](https://developer.android.com/develop/ui/views/layout/edge-to-edge).
7. **Health Connect/Samsung help and navigation:** added the supported Health Connect settings action and clear update/sharing guidance. Privacy/deletion-policy links now target the public **www** site rather than the apex MCP Worker. Missing browsers/settings activities are handled safely. The rationale accurately lists steps, sleep, heart rate and exercise, explains Keystore sessions and disabled uploads, and avoids the inaccurate blanket third-party-sharing statement. Settings navigation follows the [Health Connect API](https://developer.android.com/reference/kotlin/androidx/health/connect/client/HealthConnectClient).
8. **Bounded record previews and attribution:** the three record previews still issue one read of at most 50 records per type, explicitly identify Health Connect as the source, and now mark when a continuation page exists. They do not claim daily totals, infer Samsung origin, or create extra requests to enumerate the full history.

No health permissions were broadened: the manifest still requests only the four Health Connect **read** permissions and internet access. WHOOP read scopes and server attribution/pagination logic are unchanged. `ManualSync.ENABLE_UPLOADS=false` remains compiled in; both deletion entry-point guards and strict response-count parsing remain covered. There are no health-record inserts, background health tracking, analytics services or new authentication services.
